### 5. 安装验证（逐项确认）

所有工具装完后，逐项跑命令确认可用。**纯本地验证不需要网络/代理**；标注「需代理」才需要开 Clash Verge（终端 `export https_proxy` 或开 TUN 模式）。

**一键验证命令（推荐，合并运行）**——复制整段到终端执行，一次性输出所有工具版本、架构（arm64/x86_64）与纯本地功能验证：

```bash
echo "=== 工具装好 + 架构确认 ==="
for t in kubectl helm terraform git docker; do
  if command -v $t >/dev/null 2>&1; then
    case $t in
      kubectl) v=$(kubectl version --client 2>&1 | head -1) ;;
      helm)    v=$(helm version 2>&1 | head -1) ;;
      *)       v=$($t --version 2>&1 | head -1) ;;
    esac
    a=$(file $(command -v $t) 2>/dev/null | grep -oE "arm64|x86_64|universal" | head -1)
    printf "%-10s [OK] %-28s arch=%s\n" "$t" "$v" "$a"
  else
    printf "%-10s [MISSING]\n" "$t"
  fi
done
printf "%-10s " "code"; command -v code >/dev/null 2>&1 && code --version 2>&1 | head -1 || echo "[需装 Shell Command]"
echo "=== 纯本地功能验证（无需网络/集群）==="
helm create /tmp/tc >/dev/null 2>&1 && helm lint /tmp/tc 2>&1 | tail -1; rm -rf /tmp/tc
mkdir -p /tmp/tfv && printf "terraform {\n  required_version = \">= 1.0\"\n}\n" > /tmp/tfv/main.tf
(cd /tmp/tfv && terraform init >/dev/null 2>&1 && terraform validate 2>&1 | tail -1)
echo "=== Git 身份 ==="
printf "user.name : %s\n" "$(git config --global user.name || echo 未配置)"
printf "user.email: %s\n" "$(git config --global user.email || echo 未配置)"
```

> 说明：`docker` / `kubectl` 仅做版本+架构确认（完整功能分别需 Docker daemon 运行、K8s 集群）；联网动作（`docker pull`、下载 provider）留到 Day10/Day12 再做。所有工具 `arch=` 应为 **arm64**（Apple Silicon 原生）；若显示 x86_64 说明装了 Intel 版，需重装 arm64。

### 6. Docker 镜像加速器配置（必做，否则 Day1/Day4 拉镜像超慢）

Docker Hub 在国外，国内直连 `docker pull` 极慢且易超时。

**方案 A（推荐·国内直连·免代理）：配置 registry-mirrors**
- **阿里云 ACR（最稳，专属线路）**：登录 aliyun.com → 容器镜像服务 ACR → 镜像加速器 → 复制专属加速地址（形如 `https://xxxx.mirror.aliyuncs.com`）
- 或公共加速器（2026年9月实测可用，以本地实测为准）：DaoCloud `https://docker.m.daocloud.io`、轩辕 `https://docker.xuanyuan.me`、毫秒 `https://docker.1ms.run`、南京大学 `https://docker.nju.edu.cn`（⚠️ 中科大/网易/七牛/阿里云公共端等旧源 2026 年已失效或间歇性，勿用）
- 配置：Docker Desktop → Settings → **Docker Engine** → 编辑 JSON，加入 `"registry-mirrors"`（建议配 2-3 个做 failover）：
  ```json
  {
    "registry-mirrors": [
      "https://docker.xuanyuan.me",
      "https://docker.m.daocloud.io",
      "https://docker.nju.edu.cn"
    ]
  }
  ```
  点 Apply & Restart。验证：`docker info` 末尾应出现 `Registry Mirrors:` 列表。

**方案 B（备选·需 Clash 节点通）：Docker daemon 走代理**
- Docker Desktop → Settings → **Resources → Proxies** → 勾选 Manual proxy → HTTP/HTTPS 均填 `http://127.0.0.1:7897`（Clash Mixed Port）
- 适用：Clash 节点正常、不想配加速器时。

**若卡在「Docker Desktop 应用本体（.dmg）下载慢」**（闭源客户端，国内镜像站不提供，只能官网+代理）：
1. 开 Clash **系统代理**（GUI 应用走系统代理，与终端无关），浏览器打开 docker.com 看能否加载；能加载就点 Download for Mac (Apple Chip) 直接下；
2. 或走 DaoCloud 国内下载站 `https://get.daocloud.io/`；
3. 仍不行则手机热点或找人传 .dmg。

> 注意：此前连 GitHub 不通（终端不走系统代理），若 Clash 节点本身不稳，**优先方案 A 加速器**（pull 走国内直连，不依赖 Clash）；但软件本体下载仍需 Clash 通 docker.com 或 DaoCloud 国内站。

## 第 0 天（续）：本地环境搭建踩坑记录（SOP 素材）

> 本节点记录 Day 0 实际踩过的坑与确凿解法，供后续上传 Git 仓库沉淀为《Mac M1 DevOps 环境搭建 SOP》。每条按「现象 / 根因 / 解法 / 防复发」组织。

### 坑 1：Terraform `brew install` 报 "No available formula"
- **现象**：`brew install terraform` → `No available formula with the name "terraform"`
- **根因**：Homebrew core 已移除 Terraform
- **解法**：`brew tap hashicorp/tap && brew install hashicorp/tap/terraform`
- **防复发**：Mac 装 TF 一律走 hashicorp/tap；别在 brew 列表里乱选 terraformer / terraform-ls 等相似包（都不是本体）

### 坑 2：国内镜像站下载 HashiCorp 二进制是"假包"
- **现象**：`curl` 华为云 mirrors hashicorp 的 zip → `unzip` 报 `End-of-central-directory signature not found`
- **根因**：华为云该镜像是任意路径返回 `200 + 首页 HTML` 的 SPA 陷阱（实测 12KB HTML，非 zip）；中科大/腾讯/阿里/清华同类镜像均 404
- **解法**：唯一确凿可下真包的是官方 `releases.hashicorp.com`（25.7MB 真 zip），但国内直连需代理
- **防复发**：HashiCorp 二进制别指望国内镜像 curl；正道是终端走通 Clash 代理后 `brew tap hashicorp/tap` 安装

### 坑 3：终端 `brew tap` 连 GitHub 失败
- **现象**：`brew tap hashicorp/tap` → `fatal: unable to access github.com`
- **根因**：Clash **系统代理只影响 GUI 应用**，终端默认不走；开关 Clash 没用
- **解法**：终端手动注入 `export https_proxy=http://127.0.0.1:7897`（Clash Mixed Port，默认 7897）；或开 Clash TUN 模式让全局走代理。国内源操作前 `unset https_proxy` 直连
- **防复发**：凡 `brew tap` / 访问境外源，先 `export https_proxy`；国内源先 `unproxy`

### 坑 4：kubectl / helm 版本探测 "unknown flag: --version"
- **现象**：验证脚本里 `$t --version` 对 kubectl/helm 报 `unknown flag: --version`
- **根因**：新版 kubectl/helm 已不支持 `--version` 这个 flag
- **解法**：kubectl 用 `kubectl version --client`；helm 用 `helm version`
- **防复发**：§5 一键脚本已修；自写探测时别对这两个用 `--version`

### 坑 5：Git 全局身份未配置
- **现象**：`git config --global user.name` 为空，首次提交报错
- **解法**：`git config --global user.name "linux321"` / `git config --global user.email "deng1335770891@gmail.com"`（按实际改）
- **防复发**：新机第一步先配 Git 身份

### 坑 6：`code` 命令 not found
- **现象**：终端 `code` → command not found
- **根因**：VS Code 的 `code` 命令需手动安装到 PATH，不是扩展商店里的插件（别去搜插件）
- **解法**：VS Code 内 `Cmd+Shift+P` → 搜 `Shell Command: Install 'code' command in PATH` → 执行后重开终端
- **防复发**：装完 VS Code 第一件事就是装这个 Shell Command

### 坑 7：Docker Desktop 客户端本体下载极慢
- **现象**：docker.com 下 .dmg 卡死
- **根因**：Docker Desktop 闭源客户端，国内镜像站不提供，只能官网+代理
- **解法**：① 开 Clash 系统代理（GUI 走系统代理）+ 浏览器开 docker.com 下；② 或 DaoCloud 国内下载站 `https://get.daocloud.io/`
- **防复发**：客户端本体只能官网 / DaoCloud，别找"国内镜像"

### 坑 8：Docker 镜像加速器 2026 可用源
- **现象**：照旧教程配中科大/网易/七牛/阿里云公共端加速器 → pull 仍慢或失败
- **根因**：这些旧源 2026 年已失效或间歇性
- **解法**：用 2026-09 实测可用源做 failover：轩辕 `https://docker.xuanyuan.me`、DaoCloud `https://docker.m.daocloud.io`、南京大学 `https://docker.nju.edu.cn`；最稳是阿里云 ACR 专属加速地址
- **防复发**：§6 已固化清单；新机直接抄 §6 JSON

### 坑 9：Mac 上多个 Python 版本，误删依赖
- **现象**：`brew uses` 显示 `python@3.13` 被 `openjdk@17` 依赖、`python@3.14` 被 `openai-whisper` 依赖
- **根因**：openjdk@17、openai-whisper 各自带 Python 依赖，不能盲目 `brew uninstall python@x`
- **解法**：保留不动；项目用哪个版本显式指定即可
- **防复发**：卸载 Python 前先 `brew uses --installed python@x` 确认无依赖

### 坑 10：系统 git 优先于 brew git（arch 显示 x86_64）
- **现象**：`which git` → `/usr/bin/git`，验证里 arch=x86_64
- **根因**：系统自带 universal git 在 PATH 前，brew git 没覆盖
- **影响**：不影响使用（universal 含 arm64）
- **解法（可选）**：`brew link git --force` 让 brew 版优先；或调 PATH
- **防复发**：arm64 验证里 git 显示 x86_64 / universal 均正常，不必强求

### 坑 11：ACK 无"免费试用"入口，ASK 免费额度也不可领
- **现象**：控制台找不到 ACK 免费试用按钮；ASK 免费额度领取失败
- **根因**：托管版 ACK 只有"开通服务"免费、节点计费；无"免费试用"入口；免费额度对新用户/认证条件受限
- **决策**：**混合方案**——本地 kind/minikube 零成本日常练手 + 付费 ACK 托管版做真集群演示（练完释放节点/删集群控费）；或 ASK 按 pod 秒级计费
- **防复发**：别在控制台找"免费试用"；付费 ACK 练完务必释放，防空转扣费

### 坑 12：git clone GitHub 超时（RPC failed; curl 28）
- **现象**：`git clone https://github.com/...` → `error: RPC failed; curl 28 Failed to connect to github.com port 443 after 75015 ms: Couldn't connect to server` / `fatal: expected 'packfile'`
- **根因**：GitHub 在境外，终端/git 默认不走 Clash 系统代理（系统代理只管 GUI）；直连被墙导致 443 连不上、75s 超时
- **解法**：给 git 配代理（Clash Mixed Port 默认 7897）+ 浅克隆提速：
  ```bash
  git config --global http.proxy http://127.0.0.1:7897
  git config --global https.proxy http://127.0.0.1:7897
  git config --global http.postBuffer 524288000
  rm -rf /Users/dengzz/Documents/devops-journey-hangzhou   # 清掉上一次失败的空壳
  git clone --depth 1 https://github.com/linux321dark/devops-journey-hangzhou.git /Users/dengzz/Documents/devops-journey-hangzhou
  ```
- **防复发**：凡 `git` 操作 github.com 等境外源，先确认 git 代理已配；国内源（gitee/coding）则 `git config --global --unset http.proxy` / `https.proxy` 直连。端口以 Clash Verge → 设置 → 端口（Mixed Port）为准

## 每日执行 Tips

1. **上午：** 如果视频看不懂，立刻暂停，去 `docs/learning-resources-nav.md` 查对应技术的国内首选文档/视频，或搜国内博客。不要死磕英文源。
2. **下午：** 如果报错，先读错误日志，再搜索。记录每一个遇到的错误和解决方案，这是你面试时的宝贵素材。
3. **晚上：** 不要熬夜。复盘时，尝试用**自己的话**复述今天学到的核心概念。如果说不清楚，说明没真懂，第二天早上再看一遍视频。
4. **周末：** 如果某天进度落后，不要补到深夜，可以顺延到第二天上午，保持节奏比赶进度更重要。
